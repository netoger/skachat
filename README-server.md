# Бот skachat на виртуальном хостинге Timeweb

Площадка: виртуальный хостинг Timeweb, каталог `~/skachat`
(вне `public_html` — боту веб-корень не нужен, и заводить второй сайт
в панели не требуется).

## Почему не как в основном README

В корневом `README.md` рекомендуется Docker или systemd. Здесь нет ни
того, ни другого, а ещё `crontab` по SSH отключён и сеть до Telegram
фильтруется. Поэтому обвязка своя — четыре файла рядом с `bot.py`:

| Файл | Зачем |
|---|---|
| `net_patch.py` | Подбирает живой адрес `api.telegram.org` и подменяет разрешение имён |
| `run_bot.py` | Точка входа: сначала чинит сеть, потом зовёт `main()` из `bot.py` |
| `skachatctl.sh` | Запуск, остановка, статус, журнал, обновление |
| `check_ai.py` | Проверяет, доходит ли запрос до выбранного провайдера ИИ |

Сам `bot.py` ничего про эту площадку не знает: вся специфика вынесена
в `run_bot.py` и `net_patch.py`, поэтому обычный запуск `python bot.py`
на машине без фильтрации по-прежнему работает.

## Фильтрация сети до Telegram

DNS этой площадки отдаёт `149.154.166.110`, и соединение с ним висит до
таймаута. На проверенной площадке живым оказался `149.154.167.220` — 12 попыток из 12
за 0,08 с. На другой площадке рабочим может быть другой адрес: подбор
автоматический, вписывать ничего не нужно.
`net_patch.py` перебирает запомненный адрес → выдачу DNS → список запасных,
проверяя полное TLS-рукопожатие (часть адресов принимает TCP, но обрывает
TLS). Найденный адрес сохраняется в `data/tg_endpoint.txt`, фоновый сторож
раз в 2 минуты перепроверяет его и переключается сам, если адрес замолчит.

Имя хоста при подмене сохраняется, поэтому SNI и проверка сертификата
работают как обычно — TLS не ослаблен.

## Команды

```bash
bash ~/skachat/skachatctl.sh status     # работает или нет, настроен ли ИИ, хвост журнала
bash ~/skachat/skachatctl.sh start
bash ~/skachat/skachatctl.sh stop
bash ~/skachat/skachatctl.sh restart
bash ~/skachat/skachatctl.sh logs       # следить за журналом
bash ~/skachat/skachatctl.sh update     # git pull + зависимости + перезапуск
```

`status` отдельной строкой показывает состояние ИИ-чата — это самый частый
вопрос («бот не отвечает на текст»), и почти всегда причина в незаполненном
`.env`, а не в сбое:

```
СТАТУС: работает
ИИ-чат: НЕ НАСТРОЕН — No AI provider key is configured.
```

Журнал: `~/skachat/data/bot.log` (сам обрезается на 10 МБ).

## Секреты

Токен и ключи — только в `~/skachat/.env` (права 600, в git не попадает):

```bash
nano ~/skachat/.env
```

С этого сервера **Groq отвечает 403** без упоминания ключа — похоже на
гео-блокировку. Gemini и xAI отвечают штатной ошибкой авторизации, то есть
с настоящим ключом заработают.

Кроме трёх встроенных провайдеров бот умеет ходить в любой шлюз с
OpenAI-совместимым `chat/completions` (агрегаторы моделей, свои прокси) —
переменные `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`.
При `AI_PROVIDER=auto` шлюз выбирается первым, если заданы адрес и ключ.

Доступность провайдера с этой площадки — не данность, поэтому проверять её
надо отсюда, а не с домашней машины:

```bash
cd ~/skachat && .venv/bin/python check_ai.py
```

Скрипт печатает выбранного провайдера, адрес и модель, делает один реальный
запрос и показывает ответ. Сам ключ он не печатает — только длину и хвост.

## Автозапуск после перезагрузки

Служба переживает выход из SSH (`setsid nohup`), но не переживёт
перезагрузку сервера. `crontab` по SSH здесь запрещён, поэтому задачу
заводят в панели Timeweb → «Планировщик задач»:

- команда: `/bin/bash /home/ПОЛЬЗОВАТЕЛЬ/skachat/skachatctl.sh ensure`
  (полный путь обязателен; свой узнаете командой `echo $HOME/skachat`)
- периодичность: раз в 5 минут

`ensure` молчит, если служба уже работает, и поднимает её, если она упала.
Свои срабатывания он пишет в `data/watchdog.log`.

## Что стоит держать в голове

- **Python здесь 3.10**, новее на площадке нет. `yt-dlp` уже предупреждает,
  что поддержка 3.10 объявлена устаревшей: сейчас работает, но однажды
  очередное обновление `yt-dlp` перестанет ставиться. Тогда либо
  закрепить версию в `requirements.txt`, либо собирать Python из исходников.
- **Лимит процессов пользователя — 40.** Поэтому `MAX_CONCURRENT_DOWNLOADS`
  не стоит поднимать выше 3: каждое скачивание может позвать `ffmpeg`.
- `ffmpeg` на площадке есть (`/usr/bin/ffmpeg`).
- Скачанные файлы лежат в `downloads/` и удаляются после отправки;
  забытые чистятся через `CLEANUP_MAX_AGE_HOURS`.
